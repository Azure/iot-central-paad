The ten steps in words

Each card matches one numbered stop on the map. The “where to look” line names the real file, so a curious reader can open it next to the picture.

  1. 1 Somebody writes text files

    The app starts life as source code: TypeScript (JavaScript with type checking) using React to describe screens. Nothing here is an app yet — it is instructions.

    Where to look: src/App.tsx sets up navigation and shared providers; src/Home.tsx places Home, Explore and Activity under one runtime.

  2. 2 Configuration describes the app

    A separate configuration file states the app's name, icon, identifiers, requested permissions, minimum operating-system versions and build settings. package.json lists library version requirements; package-lock.json locks the resolved JavaScript dependencies.

    Where to look: app.config.js (iOS 16.4 and Android API 24 minimums are set here) and package.json.

  3. 3 Prebuild writes real native projects

    Expo's prebuild step turns the configuration into an ordinary Android project and an ordinary iOS project. Native dependencies arrive through Gradle on Android and CocoaPods on iOS. This repository's own native module — Swift and Kotlin code for a restricted secure WebSocket, plus a torch-availability check — is included here. That is why a general-purpose host app such as Expo Go is not enough to run PAAD.

    Where to look: modules/paad-device/README.md.

  4. 4 Build machines compile it

    The repository's automated workflow builds on two kinds of machine because Apple's build tools only run on macOS: a Linux runner produces the Android package, and a macOS runner installs the locked CocoaPods dependencies and produces an iOS Simulator app. Both include the JavaScript inside the artifact. EAS — Expo's hosted build service — is optional and is not a requirement here.

    Where to look: .github/workflows/baseline.yml (jobs named “Android bundled CI APK” and “iOS bundled Simulator”).

  5. 5 Someone installs and launches it

    An Android package can be installed on a supported Android phone or on an emulator. An iOS Simulator app runs on a Mac only: it is not an installable iPhone app, and simulator ad-hoc signing is not an Apple distribution identity. Getting onto a physical iPhone is separate, owner-controlled signing and distribution work.

    Where to look: README – build and run and the simulator guide.

  6. 6 Development mode versus a bundled build

    A development build asks a bundler called Metro, running on the developer's computer, for the JavaScript each time it starts. A bundled build from step 4 already contains it and starts by itself. An emulator or Simulator is a virtual device, which is a different idea from the app's offline simulation mode: a correctly built virtual device can make real connections with authorised credentials, and missing hardware stays unavailable rather than inventing readings.

    Where to look: guide section 4, “Which app build can I use?”.

  7. 7 The screens you actually see

    Home carries the connection map, an attention area when something needs a decision, and a short communication summary. Explore holds the tools. Activity holds observations and diagnostics. Registration, Connection details and Settings surround them. These are different views of one running session, not separate mini-apps.

    Where to look: src/Home.tsx, src/Registration.tsx, src/Settings.tsx.

  8. 8 One shared runtime

    The runtime decides which sensors are wanted, holds property values, registers the handlers for cloud commands and desired properties, and keeps unsent property drafts in memory. Drafts survive moving between tool screens; they are not saved cloud values and are not promised to survive quitting the app.

    Where to look: src/runtime/DeviceRuntime.tsx and src/runtime/propertyDrafts.tsx.

  9. 9 One shared connection client

    All screens obtain the same client from a shared context. The app-owned connection layer validates credentials, restricts which hosts may be contacted, refuses redirects, enforces deadlines and cancellation, provisions through the provisioning service, connects to the hub and implements uploads. A vendor compatibility package supplies cryptography helpers and the underlying hub messaging client; its own provisioning, upload, logging and unbounded reconnection loop are deliberately not used.

    Where to look: src/hooks/iotc.ts, connection/credentials.ts, connection/dps.ts, connection/legacyHub.ts, connection/upload.ts.

  10. 10 Three boundaries, and when writing happens

    Secure storage is written at specific moments: after a connection succeeds the credentials are persisted before the newly connected client is adopted, and settings are written when you change them. “Forget credentials” deletes the local copy and any imported Azure context. A storage failure is reported as an error, not silently ignored.

    Native hardware is a separate matter from the cloud. Sensors, location, camera and torch, Bluetooth and maps depend on real hardware, operating-system permission and build-time configuration. A denied permission or missing sensor is not a connection fault.

    Observations wrap the existing client and store a bounded amount of metadata in memory — up to 120 history rows and 64 KiB including latest facts, with repeated failures grouped. Payloads, coordinates, image bytes, keys and proof markers are not kept. Diagnostics logs are a separate list.

    Where to look: src/contexts/storage.tsx and src/observation/README.md.

Three words people mix up

React

A library for describing user interfaces as components and updating them when data changes. It is not a phone operating system and not a server.

React Native

Runs that component code so it drives real Android and iOS controls, and gives JavaScript a way to call native code. This repository uses its New Architecture.

Expo

A toolkit around React Native: compatible native modules, configuration, native-project generation and development tooling. Expo is not a replacement for React Native, and Expo Go is not sufficient for PAAD because it does not contain this repository's custom native module.

What this picture deliberately does not claim

It is not a generic “app plus backend” drawing. PAAD has no invented server of its own. The app talks to Azure services an administrator already runs; there is no PAAD API tier, database or dashboard in this repository.

Observation is not cloud monitoring. Activity shows what this app recorded about its own calls. It creates no extra cloud client and proves nothing about what Azure received.

Hardware access and cloud connection are separate questions. A working connection does not grant a sensor, and a missing sensor does not break the connection.

A successful build is not a cloud test. As of 2026-09-20, Home / Explore / Activity has retained-DPS Android emulator and iOS Simulator acceptance, including fresh cloud proof and cold restoration. The Windows emulator was updated with saved credentials and Azure context retained. The beginner guide and acceptance ledger identify the exact sources, runs and remaining limits — this is not physical-device acceptance or a physical-iPhone installation package.
